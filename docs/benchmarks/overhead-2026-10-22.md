# Profiling and reducing Alea overhead

This pass reduces sampler and diagnostic work while preserving the numerical policy. The longer native comparison records about **9% less process time in 2D, 4% in 16D, 1% in 64D and 32% for diagnostics**. Real PosteriorDB runs show no consistent overall walltime improvement. Their derivative costs and work counts remain the larger limitation.

## Where the cost goes

The native 16D Gaussian cycle profile attributes 41.70% to turning arithmetic, 9.44% to memmove, 7.78% to checked point updates and 6.05% to tree merging. This workload makes sampler overhead visible because its target is cheap. A separate diagnostics profile attributes about one third of sampled cycles to stable sorting; FFT setup is also repeated within each summary.

On the earnings model, over 90% of sampled cycles are in the shared Stan derivative backend or its thread-local-storage access. The Rust sampler is a small fraction of that workload. The sblri profile includes measurable Rust turning, enum metric dispatch and output formatting, alongside substantial backend work. These are sampled cycle profiles, not exact walltime partitions.

An offline breakdown of the previous verified 20-target cohort gives a median of per-target median retained **gradient-call ratios of 1.619** for Alea diagonal NUTS versus nuts-rs. The analogous retained **seconds-per-call ratio is 1.062**. This suggests substantially different adaptation/trajectory work is a larger part of the observed speed gap than implementation cost per evaluation. The ratios have timing variation and different adaptation policies; they do not establish equal inference efficiency or predict the gain from changing a policy. The underlying records are retained in [previous-cohort-work-cost.json](overhead-2026-10-22/previous-cohort-work-cost.json).

## Changes and Rust review

1. Scalar NUTS turning shares the normalized momentum sum between the two ordered dot products. It performs three divisions per coordinate instead of four, with the same additions, subnormal-safe divisions, finite checks and stopping decisions. The optional SIMD path remains covered by scalar-equivalence tests.
2. NUTS consumes completed phase tokens by exchanging their owned cache/momentum storage with endpoint scratch. This replaces endpoint copies while retaining coherent live caches and transactional failure. Public snapshot-copy behavior remains unchanged.
3. Small covariance-metric enum delegation methods receive ordinary inline hints. This exposes the existing concrete metric operations to consumers, including the independent benchmark workspace. There is no blanket forced-inlining policy.
4. Diagnostics select the adjacent order statistics needed for quantiles instead of fully sorting each scalar pool. Rank normalization uses in-place unstable sorting because every equal-value group receives the same rank. Signed-zero handling and interpolation operation order match the sorted reference bit for bit.
5. One local FFT plan, buffer and scratch set serves all four ESS calculations in a summary. Each calculation resets accumulated covariance; no global cache or threading policy is introduced.

The existing iterator/zip loops and allocation reuse are generally appropriate Rust. Replacing them with indexed loops was not supported by the profiles. Coherent cache copies, checks and buffer ownership still serve failure and replay contracts. Production workspace fat LTO and the independent benchmark worker release profile are unchanged. This pass adds no CPU-specific flags, approximate reciprocals or altered acceptance/adaptation rules.

The [incremental patch](overhead-2026-10-22/changes.patch) contains only these five existing source modules. The new [profiling example](../../crates/alea-runtime/examples/overhead_profile.rs) supplies bounded kernel, native-warmup and diagnostics workloads. It records draw/statistic fingerprints and actual target calls. Native draw/statistic hashing occurs after the timed numerical loop; diagnostic repetitions include a small summary checksum.

## Longer native comparison

Intel Core i7-7500U on dusk, one pinned logical CPU, serial alternating saved executables, seven rounds. No compilation ran on the measured host. Both executables use exactly the same final profiling harness; the baseline was rebuilt from the original source in an isolated workspace. All 70 process outcomes are retained. Native draw/statistic fingerprints and call counts match; diagnostic fingerprints match.

The table reports process-walltime medians for each binary. Reductions are ratios of those medians, not confidence bounds. The JSON also retains CPU times, phase clocks and every paired ratio.

| Workload | Baseline seconds | Optimized seconds | Recorded reduction |
| --- | ---: | ---: | ---: |
| Modern diagnostics, four chains | 0.856669 | 0.579079 | 32.4% |
| Fixed NUTS, 16D | 2.424280 | 2.323824 | 4.1% |
| Fixed NUTS, 2D | 1.494735 | 1.358805 | 9.1% |

The smallest improvement, about 1% in 64D, is weak walltime evidence: some pairs regress slightly. The 16D pairs all use less recorded CPU time; diagnostics improve consistently, with paired CPU ratios ranging from about 0.660 to 0.685. These remain measurements on one host and a controlled target, not broad posterior speedups.

## Real PosteriorDB workflows

Six workloads, five alternating rounds, four chains, 512 warmup/512 retained draws: 60 completed processes. The rounds reuse the three original declared repetition seed sets. Every raw draw CSV, constrained CSV, warmup trace and work record matches between the two executables after timing fields are removed. These are before/after implementation comparisons, not new sampler-quality claims.

| Target / method | Median paired process ratio | Median paired CPU ratio | Median paired retained-time ratio |
| --- | ---: | ---: | ---: |
| earnings-earn_height / nuts_cov_dense | 1.129 | 1.102 | 1.058 |
| earnings-earn_height / nuts_cov_diag | 1.002 | 1.003 | 0.993 |
| earnings-earn_height / nuts_fisher_rank4 | 1.084 | 0.972 | 1.000 |
| eight_schools-eight_schools_noncentered / nuts_cov_diag | 0.979 | 0.977 | 0.957 |
| radon_mn-radon_variable_intercept_noncentered / nuts_cov_diag | 1.001 | 1.001 | 0.994 |
| sblri-blr / nuts_cov_diag | 1.061 | 1.061 | 1.068 |

A ratio below one favors the optimized binary. This table does not establish an overall walltime win. Short processes have large startup/output/scheduling outliers, and even the longer derivative-heavy cases vary. All outliers remain in the archive. In separate instrumented runs, total user instructions fall only about 0.9% on sblri and 0.1% on earnings: unchanged derivative work dominates. The native kernel gains therefore cannot be advertised as comparable end-to-end gains on these posteriors.

The initial dense-workflow slowdown prompted a separate balanced confirmation: six alternating rounds, the same original seed set, CPU 1 on the other physical core, and per-process hardware counters. All 12 instrumented processes preserve draws, traces and work. Median paired total-time/CPU ratios are 0.975/0.976; retained time is 1.030, with pairs spanning roughly 0.906–1.106. User instructions fall only 0.07%. The initial slowdown is not reproduced as a consistent regression; this additional experiment also does not establish a consistent overall gain. It remains separate from the primary comparisons. [Dense confirmation](overhead-2026-10-22/dense-confirmation.json), [all raw outputs](overhead-2026-10-22/dense-confirmation.tar.gz).

## Validation and evidence

Fresh full-workspace validation passes **443 tests, zero failures, one ignored**, across 99 suites. All-target check, Clippy with warnings denied, rustdoc with warnings denied and formatting pass. Affected SIMD/Faer/OpenBLAS NUTS units, failure/allocation/warmup contracts and Faer runtime/session/diagnostic tests pass. Two strict-provenance/symbolic-alignment Miri tests cover the recursive NUTS oracle and internal-stage failure/panic recovery. ArviZ reference diagnostics pass; independent sorted-quantile bit checks and FFT scratch-reset checks cover the new diagnostic paths. The public API remains 6,938 items across eight crates, with five neutral variants unchanged.

Hosted CI was not dispatched. The two initial preparation failures (profiling tools not yet available remotely; libclang missing from the worker build environment) were corrected before the final measurements. The original Clippy range-style warning in the new harness and its passing rerun are retained. Main numerical source, defaults, API and dependency versions were not changed for these repairs.

# Nightly SIMD NUTS turning checks

This pass extends `alea-mcmc/simd` to the production NUTS turning arithmetic.
Previously that feature forwarded dense-metric SIMD support but did not select
explicit SIMD turning checks for identity/diagonal models. Compiler-generated
SIMD already existed in parts of the scalar baseline; this is not a claim that
Alea previously used no vector instructions.

## Profile and implementation

A fresh 128-dimensional Gaussian profile of the saved scalar executable records
5737 cycle samples, with no lost samples. Turning checks account for 42.40% of
sampled cycles and their dot-product closure another 12.74%; memmove is 10.21%,
the analytic target 6.87%, and phase energy 4.49%. These are profiling proportions,
not paired performance measurements. Raw recording:
`target/nuts-simd-2026-10-13/gaussian128.perf`.

Following the Alea skill's profile-first and numerical-safety guidance, the change
is confined to a private NUTS turning module and the sampler's nightly feature
gate. Target/metric/integrator traits, storage ownership and error semantics are
unchanged. Safe four-lane `std::simd` arithmetic validates finite values, forms
momentum sums and computes absolute maxima. It vectorizes the scaled divisions
and products but **adds products in the original scalar order**. Horizontal sum
reassociation could change a near-cancelling sign and hence the selected tree.
Dimensions below four retain the scalar path.

Positive scaling still guards against overflow; division is not replaced by a
reciprocal multiplication because the scale may be subnormal. No approximate
math, FMA substitution, unchecked memory, forced inlining or persistent velocity
cache is introduced. Both metric calls and all three enhanced turning checks
remain. Incomplete private scratch after a numerical error is never committed.
The code remains allocation-free during transitions.

Rust's [portable SIMD documentation](https://doc.rust-lang.org/std/simd/index.html)
describes this as a nightly-only API and notes that operations lower according
to available target instructions. This experiment uses the lock-pinned nightly,
not a moving `nightly` alias, and does not require `target-cpu=native` or AVX2.
The ordinary scalar build remains stable-compatible. SIMD turning also remains
enabled when Faer/OpenBLAS is selected for metric operations.

## Paired measurement protocol

Before the full comparison: three serial repetitions, alternating binary order,
logical CPU2 on the Intel i5-8250U. Same five hard targets, seeds701–704,
1024 burn-in +2048 retained draws per chain, depth9 and fixed identity geometry
as [the hard protocol](../../tools/nuts-reference/hard/PROTOCOL.md).
Both binaries use rustc1.97.0-nightly (7af3402cd, toolchain2026-04-17), release/fat
LTO and default codegen units. The difference is the `simd` feature; both include
the same extracted scalar reference implementation. Builds/tests finish before
timing. No retuning, filtering or concurrent benchmarks.

The preliminary one-round G128 smoke comparison is retained separately in
`target/nuts-simd-2026-10-13/smoke/`; it is not pooled into the final medians.
The runner records each phase, process/CPU time, affinity and executable/draw
hashes. It preserves every repetition and fails if raw draw bytes change.

```sh
nix develop --command cargo build --release --manifest-path crates/Cargo.toml -p alea-mcmc --example hard_nuts
# Save the scalar executable under a new name before the next build.
nix develop --command cargo build --release --manifest-path crates/Cargo.toml -p alea-mcmc --features simd --example hard_nuts
# Save the SIMD executable under a different new name.
taskset -c 2 PYTHON tools/nuts-reference/hard/compare.py NEW_DIRECTORY SCALAR_BINARY SIMD_BINARY --rounds 3
```

Application dependencies can enable `alea-mcmc = { path = "...", features =
["simd"] }` under the pinned nightly environment. Workspace commands can use
`--features alea-mcmc/simd`. Stable applications keep the default features.

Faster execution does not repair the hard suite's wide-funnel convergence
failure, change adaptation policy, or promote experimental Fisher warmup.
This is a paired Alea kernel experiment, not a new Stan/BlackJAX/nuts-rs timing
run or evidence of a universal backend ranking.

## CPU-native experiment protocol

After the portable comparison, a separate build changes only
`RUSTFLAGS='-C target-cpu=native'`. Before measurement, the protocol remains
three serial alternating repetitions of all five cases, CPU2, identical seeds
and settings. The baseline is the saved portable SIMD executable; the candidate
is the saved native SIMD executable. Results go to a new `native-paired/`
directory and are not pooled with the portable comparison. This flag affects
the whole compiled workload, not just turning checks, and produces a
host-specific binary unsuitable as the default redistributable artifact.

```sh
nix develop --command env RUSTFLAGS='-C target-cpu=native' cargo build --release --locked --manifest-path crates/Cargo.toml -p alea-mcmc --features simd --example hard_nuts
# Save this executable separately; retain the portable SIMD baseline.
taskset -c 2 PYTHON tools/nuts-reference/hard/compare.py NEW_DIRECTORY PORTABLE_SIMD_BINARY NATIVE_SIMD_BINARY --rounds 3
```

## Portable results

All 30 subprocesses completed. Total phase time includes burn-in and retained
sampling across four chains, excluding CSV serialization. Seconds below are
median [minimum, maximum] over the three repetitions; every outlier is retained.

| Target | Scalar | Portable SIMD | Median time reduction |
|---|---:|---:|---:|
| Gaussian32 | 1.0380 [1.0359, 2.1953] | 0.8416 [0.8387, 0.8421] | 18.9% |
| Gaussian128 | 6.0608 [6.0429, 6.0751] | 4.6235 [4.6192, 6.6623] | 23.7% |
| Banana32 | 0.5760 [0.5749, 1.2864] | 0.4689 [0.4640, 1.0831] | 18.6% |
| Logistic32 ×512 | 23.7351 [23.7170, 23.9022] | 23.9112 [23.8810, 23.9728] | −0.7% |
| Funnel10, width3 | 1.0468 [1.0461, 1.0481] | 1.0023 [0.9979, 1.0347] | 4.3% |

This is a small local timing experiment, not a confidence interval or an
all-runs-win claim. The Gaussian128 SIMD range contains a slower repetition;
banana has large outliers in both variants. Logistic shows no improvement.
The funnel remains a failed-convergence workload, not an efficiency success.

All raw draws are byte-identical between variants and repetitions, and match
the original October11 Alea hashes for all five cases. Thus that experiment's
diagnostics, divergences and actual evaluation counts remain unchanged for
these exact draws. This does not prove bitwise agreement for arbitrary targets
or CPUs. The previous Stan/BlackJAX/nuts-rs timings must not be spliced into
this paired experiment: dates, compiler and machine load differ.

Raw records, hashes and process/CPU times:
`target/nuts-simd-2026-10-13/paired/results.json`. Disassembly of the saved
portable SIMD executable confirms packed `divpd`, `mulpd` and `maxpd`
instructions in the new turning kernel. Four logical SIMD lanes need not map
to one hardware instruction on the portable baseline.

## Instruction-count check

Separate serial CPU2 `perf stat` runs of the portable scalar and SIMD binaries
on Gaussian128 counted 56,998,733,046 versus 42,183,240,949 user instructions
(26.0% fewer). User cycles were 22,745,303,188 versus 17,253,743,576. Both raw
draw hashes match the Gaussian128 hash in the paired run. Counters cover the
whole process, including serialization, not only the turning kernel. These are
single counter runs, not additional timing repetitions; cycles depend on
hardware conditions. All counters report 100% running time. Raw CSVs:
`target/nuts-simd-2026-10-13/stat-{scalar,simd}.csv`.

## Validation and handoff

Final SIMD+Faer validation passes 37 library tests, four NUTS contract tests,
two allocation tests and two sampling tests, including the executed upstream
distribution fixture and geometry/integrator moments. Strict all-target Clippy
passes for SIMD alone and SIMD+Faer. Stable1.95 passes the six scalar NUTS unit
tests. Strict-provenance Miri passes the SIMD cancellation/subnormal dot test.
Formatting and diff checks pass. The full Enzyme/OpenBLAS matrix was not rerun
for this localized optimization.

Three new SIMD unit tests cover lengths0–130, offsets0–3, scalar tails, tiny and
huge finite scales, nonfinite values in each lane, summed overflow, zero vectors
and order-sensitive cancellation. The independent recursive NUTS oracle remains
unchanged. Existing allocation checks exercise dimension7 through depth10.
These checks complement, rather than replace, whole-run byte-identical replay.

The default release `hard_nuts` executable was rebuilt without native flags
and its hash matches the saved `simd-final` portable binary. No Cargo defaults,
public APIs, adaptation policies or Fisher promotion gates changed. The Alea
skill guided profiling first, numerically faithful SIMD, and measurement of
native compilation separately. Changes remain uncommitted.

# NUTS CPU comparison

Measured October 9–10, 2026 on an Intel Core i5-8250U, pinned to logical CPU 2.
Three serial, rotated-order repetitions; no overlapping builds or tests; native
thread counts one. These are **two-dimensional** models, not high-dimensional,
GPU, Fisher-policy or whole-library benchmarks.

Four serial chains per target: 1024 discarded iterations plus 8192 retained draws
each, seeds 501–504, steps .15/.06, depth 8. No thinning or divergence removal.
[Predeclared protocol](../../tools/nuts-reference/BENCHMARK.md).

## Burn-in plus sampling time

Seconds summed over four chains, median of three repetitions:

| Target | Alea | Stan | BlackJAX/JAX | nuts-rs |
|---|---:|---:|---:|---:|
| Correlated Gaussian | 0.290 | 0.932 | 2.548 | 0.245 |
| Banana | 0.314 | 0.987 | 2.546 | 0.242 |
| Logistic | 0.301 | 1.066 | 2.337 | 0.364 |
| Width-one funnel | 0.743 | 2.084 | 4.957 | 0.599 |

Phase times exclude setup and compilation. Alea, nuts-rs and BlackJAX store draws
in memory and serialize afterwards. **Stan's native times include CSV output**
(17 significant digits, warmup saved). This is not an isolated tree-kernel comparison.

The first 1024 iterations are fixed-identity burn-in for Alea/Stan/BlackJAX, not
adaptive warmup. **Nuts-rs adapts diagonal geometry**, keeping step size fixed;
it is a differently configured baseline. Alea/nuts-rs use analytic scores;
Stan/JAX use AD. Matched adaptive-policy comparisons remain future work.

## Effective samples per second

Minimum bulk ESS over the five predeclared observables divided by total
four-chain burn-in plus sampling seconds; JIT excluded, higher is better:

| Target | Alea | Stan | BlackJAX/JAX | nuts-rs |
|---|---:|---:|---:|---:|
| Correlated Gaussian | 34,038 | 10,130 | 3,740 | 34,749 |
| Banana | 24,172 | 7,977 | 3,459 | 32,148 |
| Logistic | 47,791 | 13,059 | 6,147 | 36,840 |
| Width-one funnel | 10,132 | 3,234 | 1,463 | 11,484 |

Every repetition passes **80 diagnostic and 120 moment gates**, with zero retained
divergences. Seeds are reused: these are timing replicates, not independent
statistical ensembles. Modern diagnostics use pinned ArviZ 0.23.4.

The artifact also reports retained-only ESS/second and ESS per total integrator
step. Step counts include burn-in but are **not instrumented gradient calls**:
extra initialization/adaptation evaluations are omitted. Alea's saved coordinates
are byte-identical to the original M5 correctness output after adding timing.

Alea performs well on these small CPU targets. Nuts-rs is ahead on Gaussian,
banana and funnel ESS/second; Alea is ahead on logistic. Different metrics,
stopping rules, RNGs, AD and output paths prevent attributing all differences to
implementation overhead. No universal winner or SIMD/Faer/BLAS crossover follows.

## Startup and compilation

Full process time over **all four targets**, including initialization, imports,
JIT where applicable, output and wrappers:

| Backend | Median seconds | Observed range |
|---|---:|---:|
| Alea | 1.833 | 1.734–1.899 |
| Stan wrapper | 15.573 | 15.375–15.655 |
| BlackJAX/JAX wrapper | 39.009 | 37.642–39.384 |
| nuts-rs | 1.578 | 1.511–1.602 |

BlackJAX/JAX explicit lowering/compilation median: **20.601 seconds** for eight
scans (burn-in and retained phases for each target). Persistent compilation cache
disabled. Every timed phase uses block_until_ready, following
[JAX benchmarking guidance](https://docs.jax.dev/en/latest/benchmarking.html).
JAX is the execution/AD backend, not another independent NUTS implementation.

Stan's wrapper launches 16 processes and parses/rewrites native CSVs. Process
times are workflow costs, not sampler-kernel measurements. Rust/Stan AOT builds
were **not timed**; this is not a cold-build comparison. Medians of separate
quantities need not add up.

## Evidence and reproduction

Alea is the current uncommitted M5 scalar identity implementation, release/fat LTO.
Production sampler code was unchanged for this task. Stan 2.38.0 uses the flake's
cmdStan and existing compiled targets.stan. BlackJAX 1.5/JAX and jaxlib 0.9.2 use
the pinned float64 CPU environment. Nuts-rs 0.18.3 uses clean commit
`a762aae513bf7bb5ccb27ffc9a938a923fc837ec`, locked release/fat-LTO harness.

Raw evidence: `target/nuts-benchmark-2026-10-09/` (measurement's start date).
`results.json` records CPU affinity, binary/source hashes, all timing repetitions,
diagnostics and medians. Per-chain timing CSVs, raw draws, Stan native CSVs and
JIT timing JSONs remain alongside it. Independent correctness reports are
`0-correctness.json` through `2-correctness.json`.

Build before timing:

```sh
nix develop .#stable --command cargo build --release --manifest-path crates/Cargo.toml -p alea-mcmc --example nuts_reference
nix develop .#stable --command env CARGO_PROFILE_RELEASE_LTO=fat cargo build --release --locked --manifest-path tools/nuts-reference/upstream/Cargo.toml
```

Use Python from `tools/blackjax-reference/default.nix` and a fresh output directory:

```sh
taskset -c 2 PINNED_PYTHON tools/nuts-reference/benchmark.py target/nuts-benchmark-NEW --stan target/m5-stan-model/targets
```

Eight analyzer/benchmark tests, Rust harness formatting and Clippy passed; all
freshly measured ensembles passed the independent M5 correctness gates. Peak
memory, actual gradient counts, wider funnels, high-dimensional targets, GPU
batching and matched adaptive policies remain unmeasured here.

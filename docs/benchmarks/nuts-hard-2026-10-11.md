# Harder CPU NUTS comparison

Measured October 11, 2026 on an Intel Core i5-8250U, pinned to logical CPU 2.
Three serial repetitions with rotated backend order and native thread counts
one. No concurrent builds or tests. This extends the earlier two-dimensional
suite; it is not a tuned adaptive-NUTS, GPU or universal library comparison.

The larger suite gives a mixed result: nuts-rs has the highest measured Gaussian
ESS/second, Alea leads the passing banana configurations, and BlackJAX/JAX leads
logistic. **Every backend fails the wide-funnel convergence gates.** Nuts-rs also
fails banana under the declared fixed-step/adaptive-metric policy; its short
runtime there is not a successful speed result. No settings were retuned.

All 60 processes completed and all analyses succeeded. Every backend/target's
raw draws are byte-identical across its three timing repetitions, so timing
variation is not changed stochastic work. These are observations on one laptop,
not confidence intervals or a universal ranking.

the radius also fails. Other backends likewise fail the log-variance/radius gates.

Zero recorded divergences therefore does not establish adequate exploration.

Two useful next profiling targets emerge, without attributing causes prematurely:

- G128: nuts-rs uses 2,141,664 integration steps versus Alea's 1,491,680 yet
  takes less phase time. The shared analytic target makes per-transition math,
  turning/storage work and backend kernels worth profiling. Different policies
  and tree structures still prevent an isolated implementation-overhead claim.
- Logistic: BlackJAX/JAX is faster even including explicit compilation in its
  measured process workflow. Profile the analytic Rust likelihood/gradient
  against vectorized AD before assuming more tree micro-optimization is the
  answer. Nuts-rs takes 2,955,456 steps versus Alea's 598,416, but returns much
  higher minimum ESS; raw runtime alone overstates its efficiency disadvantage.

The next sampling comparison should predeclare matched adaptive settings and
centered/noncentered hierarchical cases. It should not silently retune the failed
banana/funnel settings and overwrite this evidence.

## Method

The [predeclared protocol](../../tools/nuts-reference/hard/PROTOCOL.md) fixes
five targets: AR(1) Gaussians in 32 and 128 dimensions, 16 independent banana
pairs, a 32-parameter logistic regression with 512 observations and normal prior,
and a centered 10-dimensional funnel with log-variance standard deviation three
(q₀ ~ N(0, 9), conditional standard deviation exp(q₀/2)).
Four serial chains use seeds 701–704, 1024 discarded and 2048 retained iterations
each, maximum depth nine. Timing repetitions reuse seeds, not new ensembles.
All coordinates and all divergences are retained.

Alea, Stan and BlackJAX use fixed identity geometry and predeclared fixed step
sizes. Their discarded iterations are **burn-in, not adaptive warmup**. Nuts-rs
uses native diagonal geometry adaptation with the same fixed step sizes and is
therefore a **different-policy baseline**. Different RNGs and trajectory stopping
rules also change work counts.

Rust samplers share an analytic density/gradient implementation. Stan and JAX
independently differentiate the same mathematical densities. Central finite
differences check every Rust target coordinate, and independent JAX AD agrees
at three deterministic points for each target. This is not independent Rust
model validation. No production sampler code changed for this benchmark.

Phase times sum burn-in and retained sampling over four chains, excluding setup
and compilation. Rust/JAX buffer draws and serialize after each timed phase;
**Stan native phase times include CSV writing**, with warmup saved and 17-digit
output. Process times additionally include imports, initialization, compilation
where applicable, formatting and wrappers. These are workflow costs, not
isolated tree-kernel comparisons.

BlackJAX 1.5 runs on JAX/jaxlib 0.9.2 CPU float64. Both scans are explicitly
lowered/compiled with persistent compilation caching disabled, and every timed
phase synchronizes completion. JAX is the execution/AD backend, not a separate
NUTS implementation. Alea uses portable release/fat LTO with default codegen
units; nuts-rs 0.18.3 uses locked release/fat LTO at clean commit
`a762aae513bf7bb5ccb27ffc9a938a923fc837ec`. Stan 2.38.0 uses its standard -O3 build.
AOT compilation was not timed; artifact zero JIT times for Rust/Stan do not
mean zero build cost.

## Diagnostic interpretation

Pinned ArviZ 0.23.4 checks every raw coordinate, mean-square radius, and every
generative/whitened coordinate for non-logistic targets. Every observable must
have finite rank Rhat ≤1.01 and bulk/tail ESS ≥400. The reported Rhat is the
maximum, and ESS the minimum, across these observables. A diagnostic failure
makes raw ESS/second insufficient evidence of reliable sampling efficiency.

Non-logistic generative means and second moments are checked against zero/one;
cross-backend raw-coordinate means are compared against Alea. Limits are six
MCSE plus .05 (quadrature MCSE for differences); MCSE is the larger of batch-128
and between-chain standard errors. Passing these broad moment checks does not
override failed convergence or divergences. No chains are dropped or budgets
retuned after seeing results.

Depth saturation counts retained draws with 511 integration steps. This is a
lower-bound proxy, not an exact count of depth-limit terminations. Retained
divergences are reported; warmup divergences are not instrumented in this suite.
Alea additionally counts actual target evaluations, including chain setup,
burn-in and sampling. Other backends have only integration-step counts; do not
present their step-normalized ESS as measured ESS per gradient evaluation.

## Evidence and reproduction

Raw artifact directory: `target/nuts-hard-2026-10-11/`. `results.json` contains all
60 runs, timings, source/binary hashes, CPU affinity, coordinate diagnostics and
cross-backend comparisons. Per-chain timing CSVs, full raw coordinates, native
Stan CSVs, compilation sidecars, process RSS and logs remain alongside it.
The [reference README](../../tools/nuts-reference/README.md#harder-cpu-workloads)
gives build, validation and execution commands. Always use a new output directory.

Validation passed: the Rust finite-difference test covering all five targets,
the independent JAX density/score checks, five hard-suite Python tests, eight
existing reference/benchmark Python tests, Rust harness formatting, Alea's hard
example Clippy with warnings denied, Python syntax checks and `git diff --check`.
All three native builds succeeded; the pinned upstream checkout remains clean.
The production sampler's broader tests were already run in the preceding
optimization task and were not rerun for these benchmark-only additions.

GNU time records peak process RSS, including runtimes and wrappers. This is
neither sampler-only heap nor the summed simultaneous memory of parent and
children. In particular the Stan Python wrapper imports JAX through the shared
dataset module; its RSS and startup time must not be attributed to native Stan.
Rust buffers one retained chain; JAX buffers warmup and retained scan output;
the Stan wrapper also parses native CSVs. Storage strategies differ.

Matched adaptive policies, additional real-data hierarchical models, parallel
chains, GPU throughput, isolated gradient kernels and SIMD/Faer/BLAS NUTS
crossovers remain separate experiments. These timings do not promote Fisher.
